# FIX-133 — collector timestamp provenance correction

Status: implemented review candidate. Full Maven/Jenkins acceptance pending.
Baseline: uploaded crypto-market-data(3).zip; Trader compatibility checked against crypto-ai(1).zip.
Number was already reserved for this defect in the Trader FIX registry. This does not renumber the collector's existing FIX-228 work.

## Confirmed cause

Recovery supplies its wall-clock observation time. The old StreamPublisher writes that into market_data_stream_version.observed_at, then compares the next Binance E timestamp against it. This can reject a genuine live close as OUT_OF_ORDER. The supplied nine event pairs show this pattern; they show missing LIVE-classified close coverage, not missing stored candles or proof of a disconnection.

## Correction and invariants

Only StreamPublisher production code changes. A new additive market_data_stream_ws_version table holds accepted WebSocket event time, payload hash and closed state per symbol/interval/open time. REST never reads or writes that ordering table. The original version table continues to describe accepted canonical writes and enforce closed-candle protection.

WebSocket duplicate/staleness checks compare against the new WS-only record. Existing lane checks still prevent a delayed older candle from gaining live authority. REST remains HISTORICAL_ONLY; unknown-time WS remains UNKNOWN_TIME; forming updates cannot reopen a closed candle. Candle, canonical version, WS version, lane, cursor and event writes commit or roll back in the same existing transaction.

Resource order remains ownership fence, symbol cursor, canonical version, WS version, lane, candle persistence. The global owner fence and symbol cursor still serialize the publisher transactions; this change does not reduce that serialization or claim new throughput capacity.

### Upgrade from contaminated versions

Do NOT populate WS versions from old canonical observed_at values: their provenance is unknown. Do NOT clear existing lanes. Those lanes were only advanced by LIVE WebSocket observations. When a WS sidecar is absent and an event is for the lane's SAME candle at or below its existing timestamp, reject conservatively as OUT_OF_ORDER. This avoids duplicate live authorization across upgrade. A strictly newer WS observation can establish its sidecar. A genuinely older different candle remains subject to the existing historical-lane rule.

This conservative rule may exclude a same-timestamp forming-to-closed transition at upgrade where the prior lane cannot prove its closed state. That narrow exclusion is deliberate; no synthetic provenance or historical promotion is used. After a sidecar exists, the existing equal-time forming-to-closed allowance uses its real WS closed state.

Do not replay or relabel the nine old pairs as LIVE. The fix applies to newly processed observations.

## Compatibility and limits

- Event columns, payload format, symbol sequence allocation and classification vocabulary are unchanged.
- No Trader code, credentials, activation flag, candle-read mode or cutover approval is changed.
- Existing market_data_candle_event claim/processed fields remain untouched by this patch; its original upsert is unchanged.
- No candle rename and no writes to crypto_ai.
- Existing FIX-228 recovery/discovery logic is byte-identical to the upload.
- Accepting a previously rejected genuine WS close can update the shared canonical candle. Consumers can therefore see corrected candle contents; zero observable data change is neither intended nor claimed.
- SharedMarketSource still redirects ordinary candle reads only in LIVE. OBSERVE alone does not migrate those reads. Trader still applies its cutover, source, freshness and observation-order gates.
- The new sidecar adds one indexed read and one write on accepted WS observations, plus storage per candle. Production latency, close coverage and retention must be monitored. No no-latency or no-missing-event guarantee is made.
- Collector repair after a lane has already advanced to a newer candle does not become live merely because this defect is fixed.

## Diagnostics

Startup: [FIX-133][ORDERING_CONFIGURATION]. Committed excluded WS closes and first WS closes encountering existing canonical versions: [FIX-133][WS_CLOSE_CLASSIFICATION], including symbol, interval, open, observed, classification and prior-version presence. Normal forming ticks are not logged individually.

Metric fix133.stream.classification counts committed observations by websocket/rest and classification when a MeterRegistry exists. It counts accepted forming observations too, even when the existing feed policy does not publish that interval's forming events. It is not a commit latency metric or a complete gap detector; use existing FIX-132 timing/lifecycle diagnostics and closed-candle coverage queries alongside it.
